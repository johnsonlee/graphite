# Read-only A16 residual allocation audit: generic lazy bindings

The next falsifiable hypothesis is to replace per-candidate whole `qualifiedNode`/`store.Node` interface boxing with one query-owned `candidateSlot`, **only in the existing generic `lazyFiltered` loop and only when `e.rowOrders == nil`**. The slot is filled from the same fully decoded owned Node after the same source `Next`. Existing label/inline-property checks, WHERE evaluation and projection then use the existing slot adapters. When row-order bookkeeping is enabled, retain the original `nodeValue` path. This is an internal representation guard, not a new planner rejection or a reduced feature set.

There is no implementation in this bundle. No query, Store, decoder, binding-map policy, source selection, task scheduler or existing freeze was edited. No application/JVM/real64 execution, CPU profile or performance measurement was run. Six read-only `go tool pprof -alloc_space` commands analyzed already-recorded heap profiles; all exited0 and their exact commands, stdout and stderr are retained. Root owns any future experiment number, implementation authorization and real-data measurement.

## Existing representation and complete decoding

`candidate.go:13–44` defines a borrowed slot with graph identity, a complete `store.Node`, optional Method descriptor and qualification flags. `freezeCandidate` copies only a directly supplied slot into the old official value. It is **not recursive**. The currently supported single-node WHERE scanner deliberately freezes published values and clears tracked scratch bindings after each candidate (`scan.go:34–68`). That existing contract does not automatically authorize using a slot in a projection consumer.

The measured query is in `lazyFiltered`'s `p.atoms == nil` branch, not the C candidate scanner. Its loop already owns a single ordinary binding map; changing or reusing other maps would be a separate hypothesis. `lazyGenericNodes` reads a full `ProjectionCandidateNode` on MAPPED and full `CandidateNode` otherwise. Each returns an owned Node before label, inline properties or WHERE. Retain every source id, type-stream order, offset/tag/count/SID read and error mapping exactly. The same helper is shared by B pagination: do not modify it. The full decoder allocates owned method/argument data, and replacing only the containing slot struct leaves their ownership and immutable references unchanged.

The slot must be allocated outside both node/source loops, with graph/store/qualification and complete node updated for each candidate. It must never be a shared global/pool, stored on the evaluator, shared with another task, or refilled before expression/project consumption finishes. Do not mutate arrays/maps inside its Node: freezing copies the containing node value while immutable owned subobjects are shared just as in the current official value. The Method flag must stay false in this path; Method and unknown-label admissions already fall through elsewhere and must remain there.

## Escape audit for a nil row-order registry

The following is a source-derived invariant over values produced by the current parser/evaluator, not a claim that an arbitrary externally forged `any` container is recursively sanitized. Input parameters and decoded Node containers cannot acquire the private slot through any query assignment: queries have no mutation operation that writes this binding into parameters or Store state. Internal test-only AST literals containing hand-crafted slots would need explicit ownership rules of their own.

| Route from the borrowed binding | Current behavior and required boundary |
| --- | --- |
| Variable, unary `+`/`DISTINCT`, CASE result, `coalesce` | May return the same pointer without freezing. This is permitted only during synchronous evaluation. A following property access understands the slot; direct projected results must pass the existing outer `freezeCandidate` in `lazyProject`. Keep eager evaluation of every function argument, including extra/unused/coalesce arguments. |
| Direct property, label, inline node constraints | `eval.Property`, `candidateSlot.property`, `matches` and `matchesLabel` explicitly handle the slot. GraphId/elementId/qualifiedId are taken from the current source; other properties follow the same NodeProperty precedence. Inline properties still evaluate against the original nil row in this generic loop. |
| Literal list/map, nested containers | `eval` freezes each inserted element/value. Nested safety is inductive: the child constructor has already frozen its own members; the outer freeze alone is insufficient. Map insertion order and duplicate-key behavior must not change. |
| List concatenation | Appending a scalar to either side freezes that inserted scalar. List-to-list concatenation preserves the existing invariant of already-owned elements. No recursive sanitizer may be assumed. |
| Comprehension and predicate scopes | `cloneRow` freezes each copied binding before local variable shadowing; comprehension projections freeze each appended value. Predicate results are scalars. Keep iteration and eager predicate/error order. |
| Index, slice, head, last, tail, reverse | These may return existing elements or shallow copies. Their safety depends on the input-container invariant above. They do not repair a container that already contains a slot. |
| properties/keys, stringify/toString, legacy whole-node adapters | propertyFunction, objectString and legacy first-argument handling freeze before type dispatch. Returned properties contain copied/owned node data, not the scratch slot. Recursive objectString consumes nested children synchronously. `coalesce` is the intentional legacy exception above. |
| Numeric/string/boolean functions and errors | Existing type assertions give the same non-number/non-string outcome for a slot and official Node. Cast-error rendering calls `javaClassName`, which freezes first. Numeric fallback, invalid functions, null handling and extra-argument error order remain unchanged. No new eager freezing of all function arguments. |
| Equality, ordered comparison, IN, DISTINCT/UNION key | equal/compare/comparePredicate/key freeze direct values; their container recursion handles owned children. Keep qualified graph identity, numeric/null semantics and key/provenance order. Compute complete projection before DISTINCT lookup, including duplicates and later-source rows after the result limit. |
| Projection row and final materialization | `lazyProject` applies `freezeCandidate` to each evaluated item before binding it into the output row. Final materialize recursively processes containers but **has no candidateSlot case**: it would not rescue an escaped pointer. Whole-node/nested output and mutation-after-next-candidate tests are mandatory. |
| Regex/case caches and function arguments | Current caches retain string patterns/results, not the node binding or argument slice. No expression executes an asynchronous callback retaining a candidate; that must remain true. |

`e.rowOrders == nil` also applies inside `lazyProject`, so its fresh scratch map is not registered anywhere. Comprehension/predicate clones freeze copied values before they can retain them. Output rows receive only owned values. The outer generic WHERE bindings stay request-local and synchronous. The pointer may remain in local scratch until reuse/return, but cannot be published to results, seen keys, metadata or another task. A cleanup guard can clear private scratch on exit if needed, without changing map allocation policy; it must not introduce checks or replace a prior panic/error. No source/task context is stored in the slot.

## Why keep the rowOrders fallback

Naively replacing `nodeValue` for every execution violates the established no-borrowed-pointer registry invariant. `lazyProject` creates bindings and calls `e.bind`; when rowOrders exists, `bind` registers that exact map by address and retains it. A projected scalar does not remove the original `n` pointer from that registry. Refill the slot for node B and an earlier scratch row now refers to B. A source-derived minimal counterexample is: create an evaluator with a nonnil registry, call `lazyProject` with a slot for A and projection `n.id`, refill the slot with B, then recursively inspect every registered row. The published scalar row may still be correct, but the registry retains a mutable borrowed value. Existing `assertNoCandidate` must reject it.

The registry can be enabled by a different UNION branch's RETURN*/whole-row aggregation, or by WTF-8 / surrogate-sensitive output ordering, even though this branch itself has no aggregate or RETURN*. Therefore plan shape alone is insufficient. The proposed dynamic guard keeps the old value path whenever the registry is nonnil. It requires no new admission rejection and no changing key order or stored scratch values.

Two alternatives are possible but not justified for the first hypothesis: freezing the candidate before registering project scratch retains the old value but adds boxing on every hit; clearing just the borrowed scratch value after projection mirrors the existing WHERE scanner but changes this consumer's registry-lifetime behavior and demands extra panic/cancel/key-order proofs. Neither is needed to cover the measured query, whose registry is nil. Keep them out of the first delta.

## Scope, scheduling and fidelity limits

Propose only the shared generic D/E loop with the registry guard. Leave `lazyFilteredScanner.next/batch`, the candidate C planner, the selected/provenance phase, B pagination, genericDistinctScanner/A15, raw projection and all Store code unchanged. Existing C functions support many slot operations but have scanner ownership transfers across source tasks; this audit is not authorization to reuse one slot across those workers. A later extension would require scanner-private ownership, join-before-reuse, selected-phase output freezing and panic/cancel cleanup proof.

The generic loop remains sequential and consumes owned Nodes in source order. Scoped bounded LIMIT and unbounded D retain their existing exit behavior. Cross DISTINCT must still exhaust required later sources to collect metadata and trigger late errors, even after 20 distinct values exist. Projection of every matching row, including duplicates and discarded unseen values past the limit, remains mandatory. Full decoding may still throw on a WHERE-rejected node. Closed Stores and canceled contexts retain the same check points, error priority and task cleanup. No context optimization is bundled with this proposal; A17 is independent.

Registry-enabled and whole-node-heavy controls should reveal fallback/freezing costs rather than being excluded.
