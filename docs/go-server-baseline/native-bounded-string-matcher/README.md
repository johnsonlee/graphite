# Native per-query bounded string matcher

This ports the two production callers of pinned main BoundedStringMatcher: raw leading projection (capacity 4,096) and finite serial raw CallSite sequences (capacity 65,536). Each query/sequence owns its matcher state; properties sharing transform, match mode and expected Java string share one matcher. Dense tables keep one byte per string. Larger tables use the original direct-mapped SID hash, replacing a colliding slot without retaining unbounded state. Both matches and misses are cached, and failures do not publish a state byte.

The serial selector is explicit: under the existing default worker policy, a preferred-persisted consumer or an ordinary source count from 2 through 39 has the serial marker. The actual main JVM verifies this for source counts 1, 2, 39, 40 and 64, with both forceSerial values and with/without a tracking callback. Empty and unbounded limits do not enter the bounded serial path. The Go raw fallback flag alone is not used as proof of that marker. Generic and parallel raw fallback behavior is outside this change.

The independent unchanged-JAR oracle in main-oracle passes 165 assertions. Go tests compare all 54 matcher-call observations, including booleans, cumulative decoder-read counts, exact exceptions/messages, and every populated cache slot. Coverage includes both capacity boundaries, collisions and unsigned hash spreading, repeated positive/negative lookups with a forbidden backing reader, all string match modes, ASCII and Java ROOT Unicode lowercase, and isolated UTF16 surrogate matches. They also check all 20 actual consumer-policy observations, nine capacity normalizations, property-independent sharing and query-local lifetime.

A separate public engine oracle captures 16 responses: 2/64 sources, clean graphs, a corrupt return-type SID, and positive/negative out-of-range caller-name SIDs, each queried twice. The Go test reproduces the exact byte mutations on fresh independent graph copies and compares complete rows or exceptions. Main stacks prove that 2-source queries enter serialRawCallSiteStringDisjunction and 64-source queries enter rawCallSiteStringProjection. A corrupt return-type SID fails full node materialization for two sources but remains unconsumed by the 64-source projection. A corrupt matching SID fails at the dense matcher array in both paths. This corrects the earlier Go leading-projection list exception to main's ArrayIndexOutOfBoundsException without changing unused-field behavior.

The fixtures and string tables here are synthetic correctness controls, never performance datasets. Oracle commands, pinned JAR/source identities, stack traces, immutable fixture checks and failed initial fixture assumptions remain in main-oracle. The native test fixtures retain all oracle records, with UTF16 inputs represented as explicit code-unit arrays. Root source changes were independently reviewed against the original bytecode and consumer-policy results.

The matcher delegates string semantics to the existing Java-compatible Go string routines. It does not port MutableString's particular memory representation, and this evidence does not claim equivalent allocation cost or a speedup. Work accounting, cancellation polling granularity, generic/parallel fallback state, configured worker overrides, remaining server functionality and formal P95 acceptance still need their respective evidence. Real64 regression captures are stored separately in ../native64-bounded-string-matcher.

Validation: go test ./internal/query -run TestBounded -count=1, go test -race ./..., and go vet ./... all exit zero. Complete logs and terminal receipts are retained. An isolated negative control restores only the two production callers from revision 1f5dd187 while retaining the new helper/tests: the public test fails on the 64-source corrupt caller-name sample, reporting IndexOutOfBoundsException instead of the required ArrayIndexOutOfBoundsException. baseline-control.json authenticates those baseline files and verifies root source remained unchanged. The initial unsupported GNU cp option is preserved in the control's first copy log; the successful copy uses /bin/cp.
