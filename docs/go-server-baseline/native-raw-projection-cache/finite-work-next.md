## Actual API and defaults

Production `serve` accepts `--cypher-work-budget` but **deliberately ignores it**. Both production route registrations construct `CypherQueryGuard(maxWorkUnits = Long.MAX_VALUE)`. The CLI help explicitly calls the option deprecated. Do not introduce a finite server default or revive that flag. The guard's constructor default of 1,000,000 applies to direct/default guard construction, not the production command. Server maximum timeout defaults to 60,000 ms. Request `timeoutMs` is read from body first, then query; it must be positive and is capped by the server maximum. No per-request work-budget option appears in these routes. The core public Kotlin API separately exposes `CypherExecutionBudget(maxWorkUnits > 0)`, `CypherExecutionContext`, and executor overloads. The budget overload creates a fresh tracker for each execution; the context overload shares cumulative counters across sequential executions. Internal scan workers share the atomic tracker. Separate concurrent executions on the same context are unsupported. Fanout deliberately passes the **same request context** to every per-graph executor. ## Exact accounting and errors

`consume(n)` first rejects negative n, then checks cancellation, then atomically decrements remaining work. `n == remaining` succeeds. Overshoot atomically saturates remaining at zero and throws `CypherBudgetExceededException`; diagnostics therefore report the configured maximum, never the attempted overrun. `consume(0)` still checks cancellation and succeeds with an exhausted budget. The exception message is exactly `Cypher work budget exceeded after N graph work units; add a selective label/filter or use a metadata-backed query`. The cancellation signal preserves its first reason. ([exception and atomic tracker](/tmp/graphite-go-main-baseline-clone-4e328b0/graphite-cypher/src/main/kotlin/io/johnsonlee/graphite/cypher/CypherExecutionBudget.kt:89))

Diagnostics are cumulative: source selections, pruning executions, sources pruned, conflicting selections, fast paths, filtered-node-limit fast paths, general fallbacks, and consumed work. Selecting a sole API-scoped source must not be counted as pruning. A filtered-node-limit fast path increments both its specialized counter and the overall fast-path counter. These diagnostics are core API data; the audited production HTTP result paths do not expose them. ([diagnostics fields](/tmp/graphite-go-main-baseline-clone-4e328b0/graphite-cypher/src/main/kotlin/io/johnsonlee/graphite/cypher/CypherExecutionBudget.kt:44), [counter updates](/tmp/graphite-go-main-baseline-clone-4e328b0/graphite-cypher/src/main/kotlin/io/johnsonlee/graphite/cypher/CypherExecutionBudget.kt:128), [planner hooks](/tmp/graphite-go-main-baseline-clone-4e328b0/graphite-cypher/src/main/kotlin/io/johnsonlee/graphite/cypher/QueryPipeline.kt:369))

The route maps a budget exception to HTTP **429**, code `cypher_work_budget_exceeded`, and the exception message. `Retry-After: 1` is set only for concurrency rejection, not budget exhaustion. Guard metrics classify the outcome as `BUDGET_EXCEEDED`. ([HTTP error mapping](/tmp/graphite-go-main-baseline-clone-4e328b0/graphite-explore/src/main/kotlin/io/johnsonlee/graphite/cli/ExploreRoutes.kt:725), [outcome classification](/tmp/graphite-go-main-baseline-clone-4e328b0/graphite-explore/src/main/kotlin/io/johnsonlee/graphite/cli/CypherQueryGuard.kt:266))

## Storage batching and cache publication order

`BufferedGraphWorkConsumer` batches only when its delegate is a batch consumer: pending work flushes at **1,024**. A plain consumer is called immediately per item; a null consumer does nothing. Flush copies pending and resets it to zero **before** delegating, so a throwing flush is not retried by a later finally. `consumeGraphWork` skips null/zero, otherwise forwards a batch or invokes the plain consumer repeatedly, capped at Int.MAX_VALUE calls for that fallback. ([batch size](/tmp/graphite-go-main-baseline-clone-4e328b0/graphite-webgraph/src/main/kotlin/io/johnsonlee/graphite/webgraph/MappedWebGraphBackedGraph.kt:2593), [batch implementation](/tmp/graphite-go-main-baseline-clone-4e328b0/graphite-webgraph/src/main/kotlin/io/johnsonlee/graphite/webgraph/MappedWebGraphBackedGraph.kt:3097))

In raw projection, cache lookup promotes LRU before charging `max(cachedIDs.size, 1)` and before rereading projected values. A miss charges inspected nodes, including nonmatches. An incomplete probe returns null without publication but still flushes its work. A completed probe publishes matched IDs **before the final finally-flush**. Consequently final-flush budget failure can leave a valid cache entry; an exception in finally can replace an earlier failure. An implementation that rolls back that cache or flushes before publication changes main behavior. ([raw provider](/tmp/graphite-go-main-baseline-clone-4e328b0/graphite-webgraph/src/main/kotlin/io/johnsonlee/graphite/webgraph/MappedWebGraphBackedGraph.kt:801))

A useful next oracle: on the four-CallSite fixture, an exhausted miss with budget one should publish an empty entry and then fail while flushing four units. A fresh context with budget one should hit that empty entry and succeed, charging one. This is a source-derived prediction, **not yet verified by the current oracle**, which uses an unrestricted counting consumer.

## Bounded first step, without a false completion claim

Implement the core request tracker and exception contract first, including exact-boundary/overshoot/zero/negative inputs, first-cancellation precedence, cumulative sequential executions and shared-worker atomics. Add optional batch consumers to raw projection and preserve lookup promotion, incomplete flush, and publication-before-final-flush. Verify against the actual main tracker and private raw provider, including failed-query cache history. Keep production server work limits at Long.MAX_VALUE.

That step covers the tracker primitive and one provider only. A subsequent checklist must enumerate every main charge site across ordinary/indexed/distinct scans, index preparation and mapped validation, metadata/method routes, generic node/edge/path traversal, and shared fanout, plus HTTP mapping and cumulative planner diagnostics. A finite-budget API must not be described as faithful across arbitrary queries until those paths have actual main comparisons. Real64 P95 remains a separate acceptance requirement.
