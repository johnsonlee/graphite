# Actual-main persisted work accounting

These are correctness observations from main `4e328b0109e13c896b74004823fb049fcb19251a`, captured independently twice with Java 17 and the original JVM flags (`-Xmx512m`, no dispatcher override or FastThrow diagnostic flag). Both public executions completed with exit 0. All captured JSON fields match exactly between repeats: 52 named cases, 187 ordered operations, all eight request diagnostics, rows/errors/stacks, cancellation/remaining work, private storage observations, and fixture identities. No performance was measured. This oracle does not establish native parity or real64 P95 acceptance.

Each case uses 40 separate mapped graph objects. The 21 fixture variants contain 352 regular files. Their immutable source is the preceding actual-main writer's prepared archive; `mutations.json` records the original archive/writer identity and every changed byte file or deletion. Runtime copies are independent per source. The six prior prepared L04/L05/L12 cases retain their exact old input and common ordered execution records; `prepared-bridge.json` preserves both original stacks and the newly extended observer data.

`main.json` and `repeat-capture/main.json` are the raw result sources. `outcomes.json` is a smaller index of each executed query, its actual work delta and first-source state. The complete original source copies, commands, stdout/stderr, compiled classes, input hashes, before/after fixture manifests, and terminal receipts are retained in the two capture directories. `schema.md` documents ordered operations and private observers. `initial-cases50.json` preserves the initial design before the two additional projection-failure cases were added, before any public capture.

## Reader, identity and successful matching observations

For the original hit64 sidecar, N=128, S=129, U=(1,128,1,128), and T=662. The successful reader costs 1862 units; a valid separate content identity plus EOF adds two. The public cold query costs **1933**: 64 failed leading-probe units, 1864 loading units, then 5 matching units. The hit1024 fixture (1100 nodes) costs **16613** publicly, including the same additional 5 matching units. These successful-query totals are actual observations; the reader formula in `mutations.json` is only a source/layout cross-check.

P01 separates reader and EOF rejection from later matching failure. Budget 1927 leaves retained initialization false; budget 1928 leaves the successfully loaded index retained while matching fails. Failed load attempts preserve the retain preference and allow a new context on the same graph objects to retry successfully. A loader success is not a successful query.

Warm public execution still attempts the 64-node leading probe. After an early LIMIT 1 cold result, the next sufficient-budget execution costs 66 and publishes the node and projected-row caches; subsequent complete cached execution costs 65. The LIMIT 2 cold query exhausts its node sequence and already publishes the node cache, making its next sufficient-budget projection cost 65. A budget of 1 therefore fails even when a retained projected row exists. The failed short-budget operations are retained, not relabelled as warm-cache successes.

Malformed magic/version, truncated primitive/identity payload, identity mismatch, CSR unique-ID/posting-end/node-order errors, checksum corruption and trailing bytes each preserve their actual partial-read or optional-file fallback behavior. For example, sufficient-budget malformed magic and truncated primitive queries cost 131; truncated identity costs 134; checksum and trailing-byte fallbacks both cost 1992. The trailing-byte control with reader-exact budget 1927 fails during later fallback, while valid EOF at that budget fails before retained publication. Full stacks retain this distinction.

Removing the independent graph identity raises the full cold successful query from 1933 to 2060; removing both identities raises it to 2189. At no-identities budget 192 the semantic string identity remains uncached; at 193 it is cached even though the later graph scan fails. A high-budget fresh context then costs 2060 instead of 2189. The semantic identity survives that earlier failure. The short independent identity file triggers derivation; a wrong but exactly 32-byte file is charged and leads to the actual identity-mismatch fallback.

## Projection failures and an additional mapped-view path

P06 mutates the SID at node 74 (CallSite index 64) while preserving the already generated sidecar and independent identity bytes. The proposed `absentzz` query was intended to preload retained state. Actual main instead takes a mapped-view path: it succeeds empty at **1863** units, initializes the mapped view, and leaves retained initialization/preference false. This is an additional configuration/path observation, not evidence of retained preloading; it remains included in the final public matrix.

The subsequent hit query actually loads the retained index and fails in NodeSerializer at 1933 units. A fresh-context retry reaches retained `projectRows`, fails on the selected bad SID at 66 units, and leaves matching-node/projected-row cache counts zero. In the bad-callee fixture, a later valid caller projection succeeds at 66 and publishes one node-cache and one row-cache entry. Repeating the bad-callee projection then fails at 65 while preserving those earlier valid cache entries. These records distinguish string matching completion, node-sequence completion and projection publication. Neither the initial mapped-view operation nor its accounting can be dropped when checking all 52 cases.

## Failed preparation and evidence limits

The first attempt stopped in Python fixture preparation after javap/javac succeeded, before any public oracle execution. Its CRC cross-check incorrectly used serialized big-endian primitive bytes. Main's CRC updater feeds each integer/long least-significant byte first. `failed-attempt-v1` retains the original inputs/source, commands, errors, classes and generated variants. The correction changes the cross-check only; all 352 generated fixture files are byte-identical to the successful capture variants. Two new complete process/directory runs followed the correction.

This bounded matrix observes sequential request contexts. It does not establish concurrent owner/waiter/Close scheduling, memory-reservation denial, every retained-load caller, all indexed/mapped matching modes, request source-selection accounting, or HTTP/server integration. `persistenceBudgetDenied` is observed as false here, not tested under actual memory denial. All eight request counters are recorded, including zero-valued counters; that does not prove those counters' triggering paths are fully implemented elsewhere. Three old private event counters and the new private persisted/cache fields require an explicitly documented native observation mapping. JVM private fields remain observable after Close; a native public observer may instead correctly return Store-closed.
