## Actual validation order and observations

Pinned `MappedCallSiteStringIndexView.kt:263–432` checks file length, magic/version, counts, identity and complete layout before starting charged validation. `PersistentIndexViewValidator` at lines 439–502 updates checksum and charges 42 header units through scalar callbacks (including one 32-unit identity-payload callback). Each primitive array is validated in blocks of at most 1 MiB and only then charged; the validator has no final flush. A failing value therefore prevents the entire current block's callback. It compares the stored checksum after the charged arrays, with no extra checksum unit. View loading checks node-ID range, but does not check node order. A separately persisted content identity costs one before these operations, while legacy identity derivation keeps its own accounting and cache publication rules.

The valid hit64 mapped load costs 1862 units, including its separate identity; the public absent query costs **1863** after one matching unit. At budget 1862, the view is already published and the later matching operation fails. At lower validation budgets the view remains absent and `mappedViewUnavailable` remains false, allowing a fresh context to retry. A cached valid view makes this query succeed with budget **1**.

Ordinary malformed-file rejection sets `mappedViewUnavailable=true`. This state is distinct from a budget abort. A subsequent query can continue through retained loading, index construction and matching, whose actual fees remain in these public records. For example, high-budget malformed magic costs **519**, checksum corruption costs **4241**, and a trailing byte costs **2380**. They are not reduced to a mapped-loader-only subtotal. The corresponding raw stacks, caches and retained flags distinguish the fallback path. Across 22 small cases, main also rewrites the malformed sidecar: original before/after manifests retain each changed SHA, and `runtime-changed-files.tar.gz` retains the actual resulting bytes for each capture. The two repeats produce identical rewritten bytes. Large-fixture executions change no files. This runtime persistence behavior is part of the evidence, not a claim of native disk-state parity. The corrected-CRC repeated-node-order file succeeds at 1863, confirming that view loading does not apply the retained reader's node-order check.

Missing graph identity yields a complete successful query cost of **1990**; missing graph and string identities yields **2119** on a fresh store. After a failure that completed the string identity at budget 129, a fresh context retries at 1990. These values include subsequent query work, not just identity or validator work.

For the first-block-invalid file, a successful public fallback query costs **262190 = 45 + 262145**: identity, header and two directory entries contribute 45, the bad posting block contributes zero, and raw fallback scans 262145 nodes. The second-block-invalid file costs **524334 = 262189 + 262145**: the first complete 262144-integer block was charged before the second block fails. At the exact pre-fallback budgets, the private unavailable flag is already true and budget-error stacks point to raw fallback. Large malformed fallbacks do not initialize a retained index here. Fresh contexts reusing the unavailable view still scan 262145 raw nodes, and budget 1 fails. This differs from the small malformed fixtures' later retained/cache paths; both behaviors remain part of the evidence.

## Scope and receipts

Raw outputs, complete states, class/message/stack errors, source/JDK/JAR hashes, commands, compiled harnesses, fixture before/after manifests and terminal receipts are retained in each main/repeat capture. The small and large input schemas remain separate so their counts and fixture identities are explicit. `verify.py` checks the declared archive files, external byte copies, frozen inputs, exact repeats, and fixture archives without launching code under test. The preceding original 52-case manifest remains valid.

These are sequential correctness controls, including the actual internal execution routes main chose. They do not prove concurrent owner/waiter/Close ordering, memory-reservation denial, every string matching mode, source-selection counters, HTTP behavior, or real64 P95 acceptance. The new unavailable flag and other private observations need an explicit native mapping. Recording all eight diagnostics does not establish that their unrelated triggering paths have been implemented.

The first archive-verifier attempt incorrectly required all runtime fixture files to remain unchanged and failed against those 22 already recorded sidecar rewrites. `verification-attempt-v1.py/json` preserves that rejected assumption. The corrected verifier checks exact changes against the original receipts and archives the resulting bytes; it does not change inputs or captured results.
