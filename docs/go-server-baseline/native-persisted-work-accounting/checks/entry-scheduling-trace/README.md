Never reuse an existing output directory. The runner accepts the original eager-core v3/v4 touched-source hashes; it rejects the subsequent lazy-core scheduler. It dynamically inventories the entire supplied module rather than assuming a file count.

The runner makes a separate module copy and uses the original replay CLI, its unchanged 1267-case workload bytes and SHA check, original first four queries in their original order, and all 64 original graph sources. It preserves the CLI's original setup GC and delay calls and adds no scheduling wait, delay, barrier, or forced work.

Fixture handling reuses `native64-fullcase-replay/audit-fixtures.py`. Every launch creates a separate APFS copy of the immutable 1152-file reference (10,338,207,518 graph bytes), verifies original and copy before/after, and only relocates the six-column source manifest into the output directory. Fixtures are never shared between traced processes. Module manifests, original/instrumented archives, exact reversible edits, unified source diff, toolchain/binary identities, all commands/PIDs/exits, raw response JSONL, trace JSONL and artifact hashes remain in the new output directory, including failed attempts.

Events cover fixed-executor creation/core start, future creation/submission/dequeue/start/cancellation/finish/join, worker source dequeue/outcome/exit, coordinator enqueue/receive/LIMIT, legacy runner/task/cancel, actual graph candidate construction, balanced source-prefix consumption, trigram anchor selection and existing absolute-position interruption polls, sequence polls, range lookup/cache observation/validation/poll/rejection/publication. Graph identity is the public graph ID in query events and the clone directory in storage events. The shared Store pointer links the two. Worker context pointers link graph operations to dequeued source indices; executor/future pointers link worker lifetime. Pointer values identify objects only within one process. `candidate_construction_return` is a defer and can occur during panic unwinding; an outcome's failure flag distinguishes failure from success.

The event buffer has 262144 slots, an atomic sequence reservation and a publication flag. It performs no hot-path I/O and emits no per-node events: polling events follow only existing checkpoints. It adds no new `ctx.Err()` calls. For trigram and sequence rejection, `entrytrace.Error` returns the original error object received from the existing single call. Full native errors remain in the replay output; trace rejection events record occurrence, not a fabricated JVM exception.

This instrumentation can perturb scheduling. Atomic reservations, reflection of pointer values, allocations, deferred hooks, and hooks inside existing locks add overhead; they are observations of the instrumented copy, not timing evidence or proof of uninstrumented causality. Sequence numbers order hook reservations, not the exact linearization of preceding channel operations. Events between queries use queryIndex -1 and are retained. Core-start events have the currently active query marker; a core delayed until another query is not attributed to its creation query. Dumps do not wait for otherwise idle pool goroutines. A dropped or unpublished slot makes the diagnostic runner fail explicitly. Raw cache differences are retained; neither public parity nor cache parity is assumed from successful trace completion.

Event numeric fields: fixed-runner `a=count,b=workers`; future `a=worker index` at creation and `a=started` at cancellation; source queue/outcome `a=source index,b=failure` where present; ordinary prefix `a=source index,b=accumulated rows,c=LIMIT`; candidate `a=source count,b=LIMIT`; mapped anchor `a=start,b=end`; polling `a=absolute posting position` (sequence poll uses visited count); range lookup `a=property,b=SID,c=found`; cache observation `a=property,b=row,c=state`; validation `a=start,b=end,c=error`; publication `a=property,b=row,c=state`. State 1 is valid and 2 invalid. No diagnostic event itself changes a cache or consumes query work.
