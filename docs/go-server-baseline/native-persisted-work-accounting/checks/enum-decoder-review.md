# Enum decoder independent review

No blocking defect or necessary missing control was identified for the bounded top-level Enum argument-count correction. Reviewed production SHA-256 `a560857181ec6b8b029005a715e4cd847330fa5ea6a43ea98c0aafcc23da244d` and test SHA-256 `51b6b4843d5312c302a2008165f856ba27da40292f3fd6998269ec7d167292f8`. This is source review only: no tests, build, Go/JVM execution, or performance run was launched by the reviewer.

Pinned main `graphite-webgraph/.../NodeSerializer.kt:488–503` reads node ID, tag, Enum type string reference, Enum name string reference, then the signed top-level argument count, and maps `0 until argCount` through `readAnyValue`. Its complete source SHA-256 is `56b438a5ec4495e547903bb906c19ff31085574b250ef4f70a611ffdddd41699`. The new `projection_node.go:100–119` branch preserves that order, accepts zero/negative top-level counts as empty, and grows the argument slice only as values are consumed. It removes the strict reader’s count-versus-remaining precheck and count-sized allocation for this branch. A very large positive count consequently reaches the first actual value/SID failure rather than failing at the count field. `d.err` is sticky and the loop stops on the first decoding error. The signed loop index does not overflow for `MaxInt32`: its final successful increment reaches the exclusive count and exits.

The type/name multi-assignment evaluates the two string-reading calls in source order. After a failed string reference, later decoder calls do not advance the reader or replace the first error. The branch rereads the header from the same mapped suffix, as the previous non-CallSite path already did; the surrounding read lock prevents Close from invalidating it. The returned argument/nested-list slices are newly allocated, scalar values are decoded immediately, and referenced strings are ordinary Go string values. No returned argument retains the mapped node-data byte slice. The unchanged Close takes the corresponding write lock. No new lifetime or cancellation registration is introduced.

`decode.go`, `store.go`, and `strings.go` are byte-identical to the frozen lazy-core module. In particular, strict `Store.Node` still invokes `d.node()`, whose Enum branch still uses `d.count()` and count-sized allocation. This change therefore does not silently relax that strict API. The new tests explicitly retain the prior strict bad-tail failure.

The test source covers both `ProjectionCandidateNode` and `MainProjectionCandidateNode` over five Java-written fixture variants: clean nested values, oversized top-level count crossing the serialized tail, invalid first/second header SID, and unknown argument-tag string fallback. It asserts exact node fields and nested values or exact typed SID index/list size, owned values after Close, and read-after-Close failure. Additional 0/-1/MinInt32 controls place an invalid immediate payload after the count and require it to remain unread. Those extra controls are correctly labeled as main-source-derived rather than additional captured JVM executions. The fixture helper extracts only the named flat variant into a fresh test directory and requires exactly 12 files; it does not modify the frozen archive.

Scope remains important: `readAnyValue` is reused unchanged. Main `NodeSerializer.kt:831–835` handles nested lists with a separate `List(readInt())` contract; Go still uses its existing nested `d.count()` validation, format check, and depth limit. This review does not claim complete malformed nested-list parity or new cancellation-between-value semantics. The parent/contract agent’s public oracle and runtime checks were still pending or running at review time, and their outcomes are not inferred from the assertions in the test source. No full-module, 201-case, real64 cache-state, or P95 acceptance is established here.
