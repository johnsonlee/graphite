## Specific gap and source order

`ordinaryLeadingRows` currently performs both its raw cold probe and its `RawProjectionMatches` hit without submitting work. The recently added batching in `mainCandidateIterator` does not cover that probe. A failed probe can subsequently enter the now-accounted serial source, making a successful final body insufficient to establish correct total charging.

Main `MappedWebGraphBackedGraph.kt:801–879` has these separate paths:

1. `limit <= 0` returns before lookup entry accounting or cache access.
2. The raw cache key contains the ordered complete predicates and LIMIT, **not projected properties or aliases**. A hit refreshes the access-order cache, then calls `consumeGraphWork(max(cachedNodeIds.size, 1))`, then rereads raw fields for the requested projection. A budget failure therefore precedes any bad projected SID on a hit.
3. A cold probe increments `inspected` and buffered work before reading the four raw CallSite SIDs. Predicate matching short-circuits; projection string lookup follows matching. It stops after enough rows, complete exhaustion, or the bounded probe size.
4. An incomplete probe returns `null` without publishing matched IDs. A complete probe or one satisfying LIMIT **publishes the raw cache before its `finally` flush**. Budget failure during that flush does not undo the publication. A failure while reading or projecting does not reach publication; the final flush may replace that earlier error with the budget exception.
5. `BufferedGraphWorkConsumer` clears pending before delegating (`:3106–3128`), so a failed submission is not repeated. Raw projection returns a list; its success is charged at the final flush, rather than at the individual yield boundaries of the fallback node sequence.

The cache is a separate graph-owned access-order map, capacity 16 (`:2633–2664`). A repeated put does not replace an entry or refresh its order. It is not a retained full string index. Cache access, retained index state, mapped view state, and their counters must be recorded separately.

## Public admission, without forcing a storage helper

Use the real `CrossGraphCypherExecutor(sources, context, false)` / native `ExecuteCrossWithOptions` with `SourceScopeApplied=false`, explicit work context, and default worker configuration. Each source must be a distinct independently opened MAPPED graph. Do not substitute 40 IDs referring to one shared Store. Use tiny correctness fixtures only.

With no configured direct-string parallelism override, the balanced gate is **40 selected sources** (`QueryPipeline.kt:171–172`). The main code also treats a configured override as balanced; do not set one to manufacture admission. A root graphId WHERE constraint, inline graphId constraint, or an explicitly scoped executor can set `preferPersistedStorage` and disable the raw-leading choice. Merely returning `n.graphId` does not constrain sources.

The primary query family is:

```cypher
MATCH (n:CallSite) WHERE n.caller_name CONTAINS 'hit'
RETURN n.caller_name AS name LIMIT 1
```

Actual source chain to verify: `tryFastFilteredNodeLimit` → `executeDirectStringFilter` → `executeDirectStringDisjunctionRows` → earlier indexed-projection decline → `projectLeadingRows(preferRaw=true)` → `rawCallSiteStringProjection`. A single supported property is valid: the direct filter is converted to a one-filter disjunction (`QueryPipeline.kt:1537–1563`). Do not infer that it uses the distinct single-property raw scan.

The earlier indexed projection declines for multiple unscoped sources (`:1891–1910`). Raw leading additionally needs no residual node-predicate factory, all CONTAINS terms of **1–4 Java UTF-16 code units**, and LIMIT **1–200** (`:1663–1666`, `:4697–4701`). `projectLeadingRows` requires CallSite or Node, direct projections of the four CallSite string properties or graphId, and filters on the four string properties (`:1832–1888`). Use `:CallSite` to avoid the Node/Annotation supplement gate. Projection expressions, literals, whole nodes, and functions decline this leading projection even if a later executor can run the query.

Raw projection permits different predicate matcher keys. Its matcher cache is shared only when transform/mode/expected are equal. The `shareStringMatcher()` restriction belongs to the **initialized mapped-view projection** (`MappedWebGraphBackedGraph.kt:780`), not the raw projection. Do not accidentally impose that restriction on the new accounting path.

The storage probe bound is `min(1024, max(64, 4*LIMIT))`. Through this public raw-leading admission, LIMIT is at most 200, so a probe inspects at most **800** nodes. A proposed 1024-node cold-leading batch-boundary case would not enter this path from the public dispatcher. All cold-leading submissions in this family are final partial batches. The subsequent serial fallback can still cross a 1024-node batch boundary.

## Required capture and comparison

Extend the existing public harness, without replacing its executor or tracker. Each request must preserve input AST/query, source IDs/order/mode, parameter map, context constructor/scope flags, maximum budget, actual command/environment, complete result or full failure, all diagnostics, and source-specific cache/index/lookup counters before and after. Record file hashes before and after each case and after Close; use only dedicated tiny copies. New-context/same-store transitions need to be explicit operations in the evidence.

Capture cold and warm independently. Preserve failed native outputs, main default-JVM null-message/stack variation, and all denominator cases. A separately labelled diagnostic JVM run may explain FastThrow, but cannot replace the default capture. A success must have the complete row/provenance/column equality, correct work and dispatcher counters, and correct raw-cache state; exit code or final body alone is insufficient. For failures, count the budget exception at the actual flush boundary, not as though every node submitted immediately.

The narrow candidate implementation suggested by this inspection is to add final-flushed cold-probe accounting and hit charging to `ordinaryLeadingRows`, preserving publication/read/flush order. This note does not authorize or claim that implementation, validate serial index/parallel accounting generally, or establish performance results.
