# Attempt17: preserve Store polling sites with nonblocking cancellation checks

This is an unmeasured single optimization hypothesis on exact root `62b92d2061b72150d76767cd07c18e351dddc7a3`, in isolated worktree `/tmp/graphite-go-projection-context-attempt17-62b92d20`. It includes committed A12/A13/A15/CDE/ordinary/tuple/main-source; it does not include B pagination or A16. No root/provider files were changed and no commit, JVM, 64-graph process, benchmark or performance measurement was run here.

Only two production files change. Five existing checks in `prepareProjectionOffsets` (entry and pre-publication), `ProjectionNodeOrder` (entry), and `ProjectionCandidateNode` (entry and each decoder read) now use nonblocking `ctx.Done()` followed by `ctx.Err()` only when Done is closed. The inline replacements preserve each check's original location. No context channel is cached across requests or workers. No locks, offsets, caches, reader operations, data ownership, exception mapping, task scheduling or decoder/WHERE/projection/provenance order changes. Other Store checks, including projection string accessors and tuple validation, remain unchanged.

The standard Context contract makes nil/open Done the live state and closed Done the canceled/deadline state. Closed contexts return their existing Err, including DeadlineExceeded and Canceled rather than a custom cancellation cause. Closed Store checks remain before context polling. File I/O and short offset-file errors still precede the post-read cancellation check; a canceled post-read request cannot publish offsets. The decoder still preserves its first failure before another context or bounds check. Cancellation can race with either the old or new observation; this does not promise identical thread interleavings or exact cancellation wall times. Invalid custom contexts whose Err fabricates cancellation while Done remains open are not cancellation evidence.
