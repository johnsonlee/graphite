## Explicit limits

Global JVM reservation admission/eviction is an existing unresolved dependency: native does not reproduce budget-denied construction fallback or temporary reservation accounting merely by maintaining final planner bytes. The author's actual repeated malformed-input oracle also found HotSpot fast-throw can omit later array exception messages; the candidate does not emulate JIT history. Java GraphWork accounting and callback-only interrupt publication schedules are not proven identical to Go context checkpoints. The added Close test verifies native safety/termination, not that arbitrary concurrent JVM query/release races produce identical errors. No claim is made for inherited ordinary/generic fallback gaps, complete scheduling determinism, all malformed sidecars, or 100% parity.
