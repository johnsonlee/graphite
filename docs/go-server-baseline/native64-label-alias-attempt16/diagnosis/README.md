# E generic DISTINCT: read-only allocation diagnosis

This audit analyzes existing real64 captures only. No application, Java process, new query workload, benchmark or performance experiment was executed, and no production source was changed. The measured base is `9ada2bf15867c192e7a53fa9a27828de6fd02075`; the candidate adds the separately verified CDE functional implementation. Both actual binaries still existed and were rehashed against their original identity receipts. Relevant source files were copied only after their hashes matched the measured source manifests. Heap profiles, original receipts, outputs, state captures and commands are preserved here.

The exact query is `MATCH (n:CallSiteNode) WHERE toString(toString(n.caller_name)) CONTAINS 'get' RETURN DISTINCT [n.caller_class, n.caller_name] AS value LIMIT 20`. The full base and candidate output hashes are both `e8537464f427227dbadb7278c1322538ba6ff12fa34312e59a2216d007f53288`, matching the saved main HTTP expectation. Elapsed diagnostic time changed 1.928697666 to 6.492682250 seconds; process user+system CPU changed 1.941437 to 6.470970 seconds; request TotalAlloc changed 2,263,578,128 to 8,392,767,504 bytes. Neither request had a GC. These are individual observations in a fixed historical sequence, not HTTP latency, cold-start evidence, P95 or a speedup conclusion. The CPU values are runtime counters, not CPU sampling profiles. No Go 1.22 CPU profile was used.

The earlier executor's sampled allocation is 2,120.38 MiB, spread across cloneRow, candidate freezing, matchesLabel, row projection and dedup keys. Its call tree includes prepareIndexedNodePositions and matchSingleNode followed by project. CDE correctly enters lazyFiltered's generic branch: nested toString is not admitted by the main-compatible direct atom compiler; label selects the CallSite ID source, but every consumed ID is fully decoded before matches and WHERE. lazy_filtered.go lines 144–156 show the order: next → nodeValue → matches → WHERE → projection. A full decode may fail even when WHERE would reject that node. This changed consumption is a functional requirement and is not an optimization regression to undo.

The new sampled allocation is 8,374,392,793 bytes (about 7.80 GiB). Two sites dominate:

| Site | Sampled flat bytes | Share |
| --- | ---: | ---: |
| traversal.go:227, boxing qualifiedNode in nodeValue | 3,218,995,088 | 38.44% |
| properties.go:140, constructing nine-entry aliases map in matchesLabel | 2,910,870,788 | 34.76% |
| ProjectionCandidateNode.func4, method parameter arrays | 391,667,392 | 4.68% |

The entire lazyProject subtree is only 488,733,052 sampled bytes (5.84%); projection map reuse is therefore not this query's principal hotspot and this is distinct from Attempt15. The WHERE bindings map in lazyFiltered is already reused. Node boxing and per-node label alias-map creation occur before filtering, while projection work occurs only for matches. Sampled byte totals are estimates; no exact node, cache-hit or function-invocation counts were emitted by this harness, and none are inferred from samples. Heap-after minus heap-before also contains post-request profiling bookkeeping, so it is not identical to the request TotalAlloc counter.

## One falsifiable next hypothesis

Replace only the local nine-entry aliases map in matchesLabel with an equivalent switch. Preserve the current strings.ToLower call, Node and Constant/ConstantNode branches, all nine exact aliases and case-sensitive target-kind comparison, and the final strings.EqualFold fallback. Do not cache label decisions by storage type: corrupted core tags and real runtime kinds must still be checked after decoding. Do not change nodeValue boxing, plan admission, caller-name conversion, projection construction or source scheduling in the same experiment.

This targets a demonstrated 2.91 GB sampled allocation site without changing any source read or value ownership. If correct, the same existing real-data request should lose that per-call map allocation site while full output, decoder consumption/error traces and other functions remain unchanged. The elapsed/CPU effect is unknown until measured; the remaining 3.22 GB node boxing cost may still dominate. A separate borrowed-slot experiment would require additional lifetime and whole-value proof and is deliberately outside this hypothesis.

Before any real-data experiment, independently compare the old helper and the switch over all 16 node kinds, Method handling at its existing caller, every alias, Node/Constant supertypes, unknown and empty kinds/labels, mixed case, Unicode casing and malformed/WTF-8 strings. Keep ToLower and EqualFold unchanged rather than substituting a different Unicode policy. Run existing CDE source/error/480-wire/history/old1048 suites and full module race/vet. Then the parent can run one isolated base/candidate pair on the same real64 fixture and warmup history; require complete response/provenance equality, and check that the map allocation disappears. Do not use synthetic allocation benchmarks or improve the result by consuming fewer nodes.

The decoder boundary must remain identical: prepare offsets → closed/context checks → selected offset (missing -1 remains absent) → payload ID/tag → complete runtime node decode. For a CallSite this is caller class/name, count/parameters/return; callee class/name, count/parameters/return; line, receiver, argument count/arguments. Negative counts, SID errors, EOF, unknown tags and non-CallSite fallback retain their existing distinctions and order. No partial-field projection or prefiltering may bypass these reads. Qualified DISTINCT must continue consuming later nodes/sources after 20 rows to merge full provenance and expose required late errors. Per-match projection order, overridden aliases, cancellation checkpoints and Close/task ownership remain untouched by the suggested switch.

`commands.json` preserves each pprof invocation and exit. Seven of eight commands succeeded; the base list request returned exit 1 because no lazyFiltered/lazyProject/ProjectionCandidateNode stack existed in that profile, which is retained as path evidence rather than silently discarded. The initial capture script aborted at that expected no-match exit after writing successful base top/cumulative output; the script was changed to record all exits and continue. There were no query executions. All evidence is read-only with respect to the original measurements; `manifest.json` seals this separate diagnosis.
